📚 Git & GitHub 학습 정리개발자란 
"내 작업물을 다른 사람에게 공유"하는 사람입니다. 이 레포지토리는 Git과 GitHub의 기본 개념부터 협업 방법까지 학습한 내용을 정리한 공간입니다.  
1. 💻 나 혼자 쓰는 Git (기본 개념 및 명령어)버전 관리를 하면 컴퓨터가 해킹당하거나 바뀌어도 안전하며, 프로젝트를 쉽게 공유할 수 있습니다. 명령어를 쉽게 다루기 위해 GUI 툴인 SourceTree를 사용합니다. 
 Clone (클론): GitHub에 이미 있는 저장소를 내 컴퓨터로 복사해서 가져옵니다.  
Commit (커밋): 내 컴퓨터(로컬)에서 변경된 파일을 내 컴퓨터에 기록(저장)하는 작업입니다. 
 Push (푸시): Commit한 파일을 GitHub(클라우드)에 올려 프로젝트 버전을 업데이트합니다.  
Pull (풀): GitHub의 변경 사항을 내 컴퓨터로 받아옵니다. 코랩 등 다른 곳에서 작업한 내용이 있다면 오류를 방지하기 위해 작업 전 반드시 Pull을 먼저 해야 합니다.  
⏪ 과거로 되돌리는 방법Reset (리셋): 해당 커밋 시점으로 완전히 되돌립니다. 'Hard' 방식을 사용하면 커밋 기록과 파일 내용이 모두 특정 시점으로 돌아가며, GitHub에 반영하려면 '강제 푸시'가 필요합니다. 
 Revert (리버트): 과거 기록은 그대로 남겨두고 특정 커밋의 변경 사항만 원상복구(덮어쓰기) 한 뒤 다시 커밋하는 방식으로, Reset보다 안전합니다.  
2. 🤝 함께 쓰는 Git (협업하기)GitHub의 가장 큰 장점은 여러 사람이 하나의 프로젝트를 멀티버스처럼 관리할 수 있다는 점입니다.  
Branch (브랜치): 현재 시점에서 갈라져 나와 다른 버전과 독립적으로 따로 작업할 수 있게 해주는 분기점입니다.  
Merge (병합): 따로 작업한 두 개의 브랜치를 하나로 합치는 작업입니다. 만약 여러 브랜치에서 같은 파일의 같은 부분을 다르게 수정했다면 "충돌(Conflict)"이 발생하므로 주의해야 합니다.  
🚀 다른 사람의 레포지토리 수정하기팀원이 팀장의 코드를 수정하거나, 권한이 없는 레포지토리에 기여할 때 사용하는 방법입니다.  
Fork (포크): 다른 사람의 레포지토리를 내 GitHub로 그대로 복사해 옵니다.  
Pull Request (PR): Fork한 내 저장소를 Clone하여 작업하고 Push한 뒤, 원본 저장소 관리자(팀장)에게 내 변경 사항을 적용(Merge)해 달라고 요청하는 기능입니다.
